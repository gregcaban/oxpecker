## Where things stand

**The generation layer has been deleted and is to be rebuilt from Fuzzilli's design.** Nothing
currently generates programs. What works: the Java harness, `compare`, `findings`, the corpora,
the UI code, and the commands `oxpecker run | diff | corpus | probe`. `pytest tests/` → 50 passed.

Why it was deleted: the IR generators (ported from the old string generator, mostly by parallel
Sonnet workers following a guide I wrote) were string generators in disguise — 105 of 133
generators emitted JavaScript text through an `Eval` escape hatch, "literals" that were code,
code-like branch labels and bare-string vocabularies. The user found it by reading the code and
was rightly disappointed; I had accepted the work on passing tests. Full account and the
specification for the replacement: `docs/what_went_wrong_with_ir_generators.md`.

User decisions (2026-10-25/26):
- Whole generation side rebuilt as a new package designed from FuzzIL; nothing carried over by
  default — a piece of the old IR comes back only by deliberate re-introduction and review.
- Old string generator deleted now, not kept until parity.
- No `Eval` in the generation layer at all; no JS text anywhere except the lifter's output;
  enums for closed vocabularies (operators, keywords), typed registries for builtins/keys/methods.
- Credit Fuzzilli in EVERY file derived from it (Apache-2.0 header naming the Swift source).
